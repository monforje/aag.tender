# Реестр компонентов

Что уже вынесено, где лежит и когда брать. Подробности — в JSDoc над самим
компонентом: там для каждого написано **КОГДА**, **НЕ ДЛЯ**, **UX**, **A11Y**
и пример. Здесь только карта, чтобы искать по одному месту.

Правило импорта: **только через публичную точку слайса** — `@/shared/ui/IconButton`,
а не `@/shared/ui/IconButton/IconButton`. Глубоких импортов в коде не осталось.

## shared/ui — примитивы, ничего не знают о доменах

| Компонент | Что это | Брать, когда |
|---|---|---|
| `Icon` | Обёртка над Solar-иконкой | Любой глиф. Размер задаётся CSS-переменной `--icon-size`, а не пропом |
| `IconButton` | Квадратная кнопка-иконка, 4 варианта поверхности, флаг `active` | Действие без текста: свернуть, настройки, уведомления, вход в панель фильтров |
| `Button` | Кнопка с текстом, 32px: `primary` (тёмная, одна на панель) / `secondary` (белая с рамкой), флаг `on` | Действие с подписью на панельной шкале: контрол полосы, триггер меню, «Очистить», «Готово» |
| `ChipButton` (в слайсе `Page`) | Тёмная «таблетка» 28px для шапки СТРАНИЦЫ | Главное действие экрана. Отдельна от `Button` намеренно — см. «Что осталось нерешённым» |
| `Badge` | Капсула состояния: тон + глиф + подпись | Значение со СМЫСЛОВЫМ цветом: статус, стадия, результат |
| `Avatar` | Инициал: воркспейс / пользователь / участник дерева | Человек или пространство представлены буквой |
| `Counter` | Счётчик: розовый (уведомление) и `muted` (количество) | Число рядом с пунктом |
| `Dropdown` + `DropdownGroup` | Выпадающее меню и группа взаимоисключающих меню | Два и более меню в одной полосе. `closeOnSelect={false}` — если внутри выбирают сериями |
| `MenuItem` | Строка меню-списка: действие, переход, заглушка | Пункт, который выполняет действие и закрывает меню |
| `MenuCheckItem` | Строка мультивыбора: квадрат-галочка или круглый значок тона | Значений выбирают несколько подряд (`role="menuitemcheckbox"`) |
| `MenuPanel` | Панель в меню: содержимое + подвал с действиями | Меню сложнее списка: мультивыбор, календарь, окно фильтров |
| `SearchInput` | Поле поиска: `capsule` (в полосе) / `field` (в панели), встроенная очистка | Поиск СУЖАЕТ список, который уже на экране |
| `SearchTrigger` | Белая капсула, открывающая модалку поиска | Поиск по всему пространству — выдаче нужен экран |
| `Modal` + `modalPart` | Модальное окно на нативном `<dialog>`: подложка, тело, части заголовка и подвала | Содержимое, ради которого прерывают работу: досье, подтверждение, форма в один шаг. Открытость — проп `open`, а не `ref.showModal()` |
| `Popover` | Панель на нативном `<dialog>`, привязанная к нажатой кнопке, с откидыванием вверх | Меню, которое обязано выйти за пределы своего контейнера — из ячейки таблицы с `overflow-x:auto`, из области прокрутки. Внутри полосы фильтров хватит `Dropdown` |
| `Table` + `tableCell` | Таблица данных: лента во всю ширину `<main>` + модификаторы ячеек. `layout="fixed"` — ширины из `<colgroup>`, а не из содержимого | Плотный список записей, который читают по колонкам; `fixed` — когда колонки СРАВНИВАЮТ между собой |
| `FacetFilter` | Окно «критерии \| значения» с поиском внутри критерия | Фильтр по нескольким полям, у каждого МНОГО значений |
| `InlineInput` | Значение, которое правится на месте: в покое неотличимо от текста, заливка по наведению, кольцо по фокусу | Поле сводки или карточки, где значения читают чаще, чем правят. Форму, которую пришли заполнять, — не им |
| `CalendarMonth` | Один месяц: шапка с листалкой, месяц списком и год СЕТКОЙ 3×7 в `Popover`, сетка дней. Геометрия shadcn/ui `<Calendar>`, но списки НЕ нативные — раскрытый `<select>` рисует ОС | Деталь внутри `DatePicker` и `RangeCalendar` — на страницу не ставится |
| `DatePicker` | ОДНА дата: кнопка на поверхности `.inline-edit` + поповер с `CalendarMonth`. Раскладка Date Picker из shadcn/ui, но без глифа и без фиксированной ширины | Дату задают в форме или карточке. Формат показа всегда ДД.ММ.ГГГГ |
| `RangeCalendar` | Период: два независимых месяца поверх `CalendarMonth`, поля ДД.ММ.ГГГГ | Период задают в фильтре или форме — мышью или набором |
| `ColorPicker` | Выбор произвольного цвета: площадка HSV, оттенок, прозрачность, пипетка, ввод в HEX/RGB/HSL (геометрия shadcn/ui color-picker) | Цвет выбирает ЧЕЛОВЕК и смысла у него нет — пометка колонки, подсветка. Для цвета СО СМЫСЛОМ (статус, стадия) — `Badge` и тоны `--cu-tone-*`. Самопроверка: `bun src/shared/ui/ColorPicker/color.check.ts` |
| `Breadcrumbs` | Крошки «родитель / текущий» | Открыт дочерний экран (уровень 3+) |
| `ScrollArea` + `useScrolled` | Скролл-граница и тень липкой шапки | Контент, который может перерасти вьюпорт |
| `Screen`, `PageHeader`, `PageTitle`, `PageActions`, `ScreenPlaceholder` | Обвязка страницы | Любая страница в `<main>` |
| `SecondaryHeader` | Таблист вкладок экрана | `header` — второй слот шапки, фильтр среза данных (`<PageHeader withSecondary>` рядом снимает свою нижнюю границу); `canvas` — та же полоса в теле страницы, на холсте `<main>`, выше и крупнее (вкладки карточки тендера) |
| `TreeRow`, `TreeToggle`, `TreeBranch`, `GroupTitle` | Строки дерева | Панель со структурой раздела |
| `NestedTreeNode` + `visibleNestedChildren` | Вложенный узел: родитель + дети + линия + тоггл | У пункта 2+ дочерних экрана И родитель ведёт на свой |
| `Tree` | Универсальное дерево: `items` + `activePath` + `onNavigate` | Список строк таксономии с кликабельным пунктом-маршрутом |
| `VisuallyHidden` | Текст только для скринридеров | Иконочный контрол, чей смысл шире короткой подписи |

## pages — экраны под маршрутами

| Страница | Маршрут | Из чего состоит |
|---|---|---|
| `TenderRegistryPage` | `/tenders/registry` | Вкладки + `RegistryFilters` + `Table`. Своего CSS-модуля нет: чистая композиция |
| `TenderPage` | `/tenders/registry/:id` | Крошки + `TenderSummary` (сводка: название с раскрывающейся капсулой статуса + четыре редактируемых поля сеткой 2×2) + `SecondaryHeader variant="canvas"` (разделы карточки) + `TenderCompare` на вкладке «Сравнение», заглушка на остальных |

В слайсе карточки локальных компонента два. `TenderCompare` — раздел
«Сравнение»: таблица, где шапка каждой колонки подрядчика это КАРТОЧКА
(имя по центру, сегментная шкала заполнения КП, процент, сумма, статус),
колонка красится по месту в ранжире и перекрашивается рукой, а сама карточка
открывает досье в нативном `<dialog>`. Ради него `Table` публикует модификатор
`tableCell.card` — «ячейка целиком отдана своему содержимому». Второй —
`TenderSummary`: шапка со сводкой тендера — название с капсулой статуса справа,
под ними карточка с четырьмя полями в сетке 2×2 (заполнение по столбцам: 1 3 /
2 4). Капсула статуса в покое схлопнута до глифа и разъезжается под курсором —
это рецепт 10 каталога состояний, применённый здесь единственный раз. Значения
полей — **инлайновые поля ввода**: в покое неотличимы от текста, заливка по
наведению, кольцо по фокусу; срок — нативный `<input type="date">` (одиночная
дата берёт `DatePicker`, период — `RangeCalendar`). Строка поля и
подсказка на `::after` (`data-hint` + `<VisuallyHidden>` для скринридера)
остаются локальными: выносить в `shared` есть смысл со второго потребителя, не
раньше — доменного знания в строке ровно на подбор полей, а `<Tooltip>` без
второго вызова примитив, спроектированный вслепую.

Локально в слайсе реестра остался ровно один компонент — `RegistryFilters`:
полоса фильтров. Она композиция общих примитивов плюс раскладка полосы и
индикаторы поверх кнопок без подписи; всё остальное (окно фильтров, календарь,
строка мультивыбора, поле поиска, кнопки) уехало в `shared/ui`.

## Состояния: одна шкала на всё

Токены в `src/app/styles/global.css`, там же **каталог из десяти рецептов
взаимодействия** — закрытый список того, как элемент отвечает на курсор и фокус.
Десятый (раскрытие подписи под курсором, `0fr → 1fr`) — единственное
разрешённое изменение размера под курсором, и разрешено оно тремя условиями
сразу: элемент не кликабельный, справа от него в потоке пусто, скрытая подпись
— третий канал, а не единственный. Применён один раз, в капсуле статуса
`TenderSummary`.

| Токен | Значение | Когда |
|---|---|---|
| `--cu-state-hover-subtle` | `rgba(0,0,0,.05)` | Крупная поверхность: строка списка, пункт меню, строка таблицы |
| `--cu-state-hover` | `rgba(0,0,0,.06)` | Компактный контрол 22–32px; он же — текущее состояние строки |
| `--cu-state-hover-strong` | `rgba(0,0,0,.09)` | Контрол, у которого в покое уже есть заливка (`Button on`, `IconButton active`) |
| `--cu-state-ring` | `0 0 0 1px rgba(0,0,0,.16)` | Белая капсула на светлом фоне — заливать нечем |
| `--cu-focus-ring` | `2px solid rgba(0,0,0,.25)` | Фокус с клавиатуры |
| `--cu-fill` / `--cu-fill-subtle` | `.06` / `.035` | Заливка в покое |

Ступень выбирается по двум правилам, а не «как у соседнего компонента»:
**площадь обратно пропорциональна плотности** (большой поверхности хватает более
слабой заливки) и **контрол с собственной заливкой шагает вверх** (иначе hover
не читается поверх своего же фона).

### Семантические тона

Живут в токенах `--cu-tone-*` (`global.css`), а не по месту: потребителей
четверо — `Badge` в таблице, `MenuCheckItem` в фильтре и его круглый значок,
плюс колонка подрядчика в сравнении КП (заливка `color-mix` в 7% и полоска
карточки).

| Тон | `--cu-tone-*` | `-ink` (текст поверх заливки) | `-fill` (.1) |
|---|---|---|---|
| info | `rgb(29,110,220)` | `rgb(24,88,176)` | `rgba(29,110,220,.1)` |
| success | `rgb(0,138,86)` | `rgb(0,116,72)` | `rgba(0,138,86,.1)` |
| warning | `rgb(214,119,10)` | `rgb(176,96,6)` | `rgba(214,119,10,.1)` |
| danger | `rgb(233,61,130)` | `rgb(197,40,105)` | `rgba(233,61,130,.1)` |
| neutral | `rgb(150,150,150)` | secondary | `--cu-fill` |

`warning` появился вместе со сравнением КП: у ранжира три деления — «лучшее /
среднее / худшее», и среднему в шкале info/success/danger места не было.

Три роли путать нельзя: сам цвет (точка, значок, залитый чекбокс), `ink` (текст
на подложке — исходный цвет на своей же заливке не добирает контраста) и `fill`
(тихая подложка). Нейтральный намеренно не цветной: «черновик» — отсутствие
состояния.

Тип `Tone` экспортирует `shared/ui/Badge`; доменные таблицы статусов
типизируются им, чтобы не заводить своей палитры. Правило: **одно состояние —
один тон и один глиф во всех местах сразу**, и то и другое описано ОДИН раз
(`STATUS` в `entities/tender`).

## Что осталось нерешённым

- **Две тёмные кнопки**: `ChipButton` (28px, шапка страницы — число из эталона)
  и `Button variant="primary"` (32px, панельная шкала). Слить нельзя, не сдвинув
  пиксели; у `ChipButton` и `PageActions` сейчас НЕТ ни одного потребителя —
  они ждут возвращения экрана с действиями в шапке.
- **Радиусы не следуют размеру**: 28px → 7px, 32px → 6px, 22px → 5px, 32px на
  рейле → 8px. Поэтому `IconButton` кодирует поверхность вариантом, а не парой
  `size`+`radius`. Унификация изменит пиксели — нужно отдельное решение.
- **`:focus-visible` есть не у всех**: добавлен у `IconButton`, `Button`,
  `MenuItem`, `MenuCheckItem`, `SearchInput`, дней календаря, строк дерева и
  тоггла; у крошек, пунктов рейла и переключателя воркспейса — пока нет.
- **Клавиатура в меню**: `MenuItem` уже `role="menuitem"` с `tabIndex={-1}`
  (заготовка под roving tabindex), но стрелочной навигации ещё нет.
- **`Breadcrumbs` завязан на react-router** (`<Link>`). Осознанно: реюз внутри
  этого приложения. Для выноса в пакет понадобится проп `renderLink`.
- **`Table` не умеет сортировку и выбор строк**: сейчас это геометрия + палитра
  и ничего больше. Появятся — добавлять в примитив, а не в страницу.
- **`FacetFilter` не виртуализирован**: потолок в 50 строк вместо этого. До
  списков, где потолок начнёт мешать, вопрос не стоит.
- **Фильтры не сохраняются**: состояние живёт в `useState` страницы, в URL его
  нет. Значит, ссылку на отфильтрованный реестр не отправить и F5 её сбрасывает.
- **Избранное и цвет колонки в сравнении КП — тоже `useState` страницы**: та же
  цена, что у фильтров, и по той же причине (сервера нет). Отметка «в
  избранном» пока ничего не делает, кроме того что видна.
- **`<Modal>` и `<Popover>` не умеют вложенности**: панель, открытая из окна,
  попадёт в тот же верхний слой и закроется вместе с ним. Случая пока нет;
  появится — это про `closedby` и стек, а не про третий `<dialog>`.
- **Контракт ширины колонок живёт в модуле `TenderCompare`**, хотя доменного в
  нём ничего нет: `<Table layout="fixed">` даёт режим, а сама формула (пол,
  потолок, равная доля, остаток названию) — на странице. Обобщать пришлось бы
  не числа, а РОЛИ колонок; со вторым таким экраном это `tableCol` рядом с
  `tableCell`, тем же приёмом. Разбор — Часть XII `DESIGN-NOTES.md`.
