# Реестр компонентов

Что уже вынесено, где лежит и когда брать. Подробности — в JSDoc над самим
компонентом: там для каждого написано **КОГДА**, **НЕ ДЛЯ**, **UX**, **A11Y**
и пример. Здесь только карта, чтобы искать по одному месту.

Правило импорта: **только через публичную точку слайса** — `@/shared/ui/IconButton`,
а не `@/shared/ui/IconButton/IconButton`. Глубоких импортов в коде не осталось.

## shared/ui — примитивы, ничего не знают о доменах

| Компонент | Что это | Брать, когда |
|---|---|---|
| `Icon` | Обёртка над Solar-иконкой | Любой глиф. Размер задаётся CSS-переменной `--icon-size`, а не пропом |
| `IconButton` | Квадратная кнопка-иконка, 4 варианта поверхности, флаг `active` | Действие без текста: свернуть, настройки, уведомления, вход в панель фильтров |
| `Button` | Кнопка с текстом, 32px: `primary` (тёмная, одна на панель) / `secondary` (белая с рамкой) / `danger` (необратимое действие, тоже одна), флаг `on` | Действие с подписью на панельной шкале: контрол полосы, триггер меню, «Очистить», «Готово» |
| `ChipButton` (в слайсе `Page`) | Тёмная «таблетка» 28px для шапки СТРАНИЦЫ | Главное действие экрана. Отдельна от `Button` намеренно — см. «Что осталось нерешённым» |
| `Badge` | Капсула состояния: тон + глиф + подпись | Значение со СМЫСЛОВЫМ цветом: статус, стадия, результат |
| `Avatar` | Инициал: воркспейс / пользователь / участник дерева | Человек или пространство представлены буквой |
| `Counter` | Счётчик: розовый (уведомление) и `muted` (количество) | Число рядом с пунктом |
| `Dropdown` + `DropdownGroup` | Выпадающее меню и группа взаимоисключающих меню | Два и более меню в одной полосе. `closeOnSelect={false}` — если внутри выбирают сериями |
| `MenuItem` | Строка меню-списка: действие, переход, заглушка; с пропом `checked` — радиопункт (`menuitemradio`) с галочкой | Пункт, который выполняет действие и закрывает меню, или одиночный выбор |
| `MenuCheckItem` | Строка мультивыбора: квадрат-галочка или круглый значок тона | Значений выбирают несколько подряд (`role="menuitemcheckbox"`) |
| `MenuPanel` | Панель в меню: содержимое + подвал с действиями | Меню сложнее списка: мультивыбор, календарь, окно фильтров |
| `Segmented` | Сегмент-контрол режимов: тихий трек, отмеченная опция наливается тоном своего режима (`tone`), иконка-декор 14px (`icon`); один канал отмеченности — заливка. radiogroup, roving tabindex, стрелки по APG | Два-четыре частых взаимоисключающих РЕЖИМА (пресеты сравнения). Растущий список значений — `Dropdown` |
| `CellPopup` + `useCellPopup()` | Подсказка-объяснение пометки на нативном `<dialog>`: тайминги NN/g (350/500 мс), мост курсора, Escape/скролл. Один попап на экран, целей много — механика в хуке (`bind(data)` на цель, `view` рядом с таблицей); тип обработчика экспортируется как `CellPopupBind` | Объяснить пометку «почему так» по наведению или фокусу: причина аномалии, критерий минимума. Панель по клику — `Popover`, окно — `Modal` |
| `SearchInput` | Поле поиска: `capsule` (в полосе) / `field` (в панели), встроенная очистка | Поиск СУЖАЕТ список, который уже на экране |
| `SearchTrigger` | Белая капсула, открывающая модалку поиска | Поиск по всему пространству — выдаче нужен экран |
| `Modal` + `modalPart` | Модальное окно на нативном `<dialog>`: подложка, тело, части заголовка и подвала | Содержимое, ради которого прерывают работу: досье, подтверждение, форма в один шаг. Открытость — проп `open`, а не `ref.showModal()` |
| `Popover` | Панель на нативном `<dialog>`, привязанная к нажатой кнопке, с откидыванием вверх | Меню, которое обязано выйти за пределы своего контейнера — из ячейки таблицы с `overflow-x:auto`, из области прокрутки. Внутри полосы фильтров хватит `Dropdown` |
| `Table` + `tableCell` | Таблица данных: лента во всю ширину `<main>` + модификаторы ячеек. `layout="fixed"` — ширины из `<colgroup>`, а не из содержимого. `stickyHead` — шапка прилипает к скроллу страницы нативным sticky (между таблицей и скроллом не должно быть своего скроллблока) | Плотный список записей, который читают по колонкам; `fixed` — когда колонки СРАВНИВАЮТ между собой; `stickyHead` — длинная таблица, строки едут под неподвижной шапкой |
| `FacetFilter` | Окно «критерии \| значения» с поиском внутри критерия | Фильтр по нескольким полям, у каждого МНОГО значений |
| `InlineInput` | Значение, которое правится на месте: в покое неотличимо от текста, заливка по наведению, кольцо по фокусу | Поле сводки или карточки, где значения читают чаще, чем правят. Форму, которую пришли заполнять, — не им |
| `CalendarMonth` | Один месяц: шапка с листалкой, месяц списком и год СЕТКОЙ 3×7 в `Popover`, сетка дней. Геометрия shadcn/ui `<Calendar>`, но списки НЕ нативные — раскрытый `<select>` рисует ОС | Деталь внутри `DatePicker` и `RangeCalendar` — на страницу не ставится |
| `DatePicker` | ОДНА дата: кнопка на поверхности `.inline-edit` + поповер с `CalendarMonth`. Раскладка Date Picker из shadcn/ui, но без глифа и без фиксированной ширины | Дату задают в форме или карточке. Формат показа всегда ДД.ММ.ГГГГ |
| `RangeCalendar` | Период: два независимых месяца поверх `CalendarMonth`, поля ДД.ММ.ГГГГ | Период задают в фильтре или форме — мышью или набором |
| `ColorPicker` | Выбор произвольного цвета: площадка HSV, оттенок, прозрачность, пипетка, ввод в HEX/RGB/HSL (геометрия shadcn/ui color-picker) | Цвет выбирает ЧЕЛОВЕК и смысла у него нет — пометка колонки, подсветка. Для цвета СО СМЫСЛОМ (статус, стадия) — `Badge` и тоны `--cu-tone-*`. Самопроверка: `bun src/shared/ui/ColorPicker/color.check.ts` |
| `Breadcrumbs` | Крошки «родитель / текущий» | Открыт дочерний экран (уровень 3+) |
| `ScrollArea` + `useScrolled` | Скролл-граница и тень липкой шапки | Контент, который может перерасти вьюпорт |
| `Screen`, `PageHeader`, `PageTitle`, `PageActions`, `ScreenPlaceholder` | Обвязка страницы | Любая страница в `<main>` |
| `SecondaryHeader` | Таблист вкладок экрана | `header` — второй слот шапки, фильтр среза данных (`<PageHeader withSecondary>` рядом снимает свою нижнюю границу); `canvas` — та же полоса в теле страницы, на холсте `<main>`, выше и крупнее (вкладки карточки тендера) |
| `TreeRow`, `TreeToggle`, `TreeBranch`, `GroupTitle` | Строки дерева | Панель со структурой раздела |
| `NestedTreeNode` + `visibleNestedChildren` | Вложенный узел: родитель + дети + линия + тоггл | У пункта 2+ дочерних экрана И родитель ведёт на свой |
| `Tree` | Универсальное дерево: `items` + `activePath` + `onNavigate` | Список строк таксономии с кликабельным пунктом-маршрутом |
| `Stack`, `Inline`, `Grid`, `Divider` | Раскладка: колонка / ряд / сетка равных ячеек / линия. Зазоры — типизированными ступенями шкалы (`gap={3}`, не пиксели) | Группа «сверху вниз», полоса контролов, плитки одинаковой природы, разделитель секций. Box/Container/Spacer намеренно НЕ существуют — см. JSDoc слайса |
| `Text`, `Heading` | Типографика: строка с кеглем/тоном из шкалы и заголовок h1–h3 с уровнем семантики | Подпись под полем (`sm`+`secondary`), метаданные карточки; новый заголовок поверхности. Заголовок страницы — `<PageTitle>`, не он |
| `ButtonGroup` | Ряд связанных кнопок: `joined` (слепленные края) или зазор шкалы | 2–3 действия одной природы рядом. Взаимоисключающие режимы — `Segmented` |
| `Link` | Ссылка: `to` → роутер, `href` → внешняя с target/rel и стрелкой наружу | Переход, который не меняет данные. Действие — `Button` |
| `Field` (+`useFieldControl`) | Поле формы: подпись + контрол + подсказка/ошибка; связки id/aria ставятся контекстом | Обёртка над `Input`/`Textarea`/`Select`. Чекбоксы и свитчи — не здесь |
| `Input` + `Textarea` | Однострочное поле и многострочный собрат на одной поверхности (32px, как вторичная кнопка) | Ввод значения в форме или панели. Поиск — `SearchInput`, значение из списка — `Select`, правка в сводке — `InlineInput` |
| `Select<T>` | Выбор одного значения: триггер-поле + меню проекта (`Dropdown`+`MenuItem`), опционально «Очистить» | Значение выбирают, а не вводят. Мультивыбор сериями — `MenuCheckItem`; значения непредсказуемы — `Input` |
| `Checkbox` | Независимая отметка: нативный инпут под коробкой, есть indeterminate | «Да/нет» в фильтрах и формах вне меню (в меню — `MenuCheckItem`). Режим мгновенного действия — `Switch` |
| `Radio` + `RadioGroup` | Взаимоисключающий выбор: группа даёт name, значение и aria-label | 2–4 варианта, которые ВСЕГДА видны. Больше — `Select`; режимы без панелей — `Segmented` |
| `Switch` | Выключатель режима, применяющегося сразу: role="switch", подпись обязательна | Настройка вида без формы. Отметка до «Готово» — `Checkbox` |
| `Card` (+`cardPart`) | Белая поверхность карточки: хэйрлайн-край, радиус 12, части head/title/foot | Сгруппированный блок на холсте страницы. Окно — `Modal`, панель у кнопки — `Popover` |
| `Skeleton` | Заглушка «грузится»: серый блок волной на месте будущего содержимого | Контур реального содержимого известен. Пусто — `EmptyState`, ошибка — `ErrorState`, процесс без места — `Spinner` |
| `EmptyState` | Честное «здесь пусто»: глиф в круге + заголовок + описание + одно действие | Выборка не нашла записей, раздел ждёт данных. Экран целиком — `ScreenPlaceholder`, ошибка — `ErrorState` |
| `ErrorState` | Ошибка загрузки области: та же форма, тон danger и «Повторить» | Запрос не удался. «Нет доступа» — текст без кнопки, не это |
| `Pagination` | Постраничная навигация: окно страниц с краями и многоточием, сама исчезает при pageCount ≤ 1 | Хвост таблицы или списка, разбитого на страницы. Панели — `Tabs` |
| `Tabs` | Вкладки поверхностей с полной клавиатурой (roving tabindex, APG) | Переключение панелей внутри окна/боковика. Таблист в шапке страницы — `SecondaryHeader` |
| `Drawer` (+`drawerPart`) | Боковая панель на нативном `<dialog>`: въезжает справа, открытость — проп | Детали записи рядом со списком. Прерывание работы — `Modal` |
| `Tooltip` | Короткая подсказка по наведению/фокусу: пауза 350 мс, над триггером, гаснет при скролле | Объяснение, которое не нужно для задачи. Ячейки таблицы — `CellPopup`, панель — `Popover` |
| `Alert` | Сообщение в потоке страницы: тихая подложка тона, глиф по умолчанию, крестик опционален | Результат операции или предупреждение НАД содержимым. Мгновенное подтверждение — `Toast`, статус-значение — `Badge` |
| `Spinner` | Крутящееся разомкнутое кольцо: sm/md, цвет наследует, подпись для скринридера | Короткое ожидание внутри контрола. Контур экрана — `Skeleton`, проценты — `Progress` |
| `Progress` | Полоса прогресса: value 0–100 или неопределённый режим без процентов | Измеримый ход процесса. Без процентов на постоянке — `Spinner` |
| `Toast` (`ToastProvider` + `useToast()`) | Угловые самозакрывающиеся подтверждения; провайдер смонтирован в `app/index.tsx` | «КП отправлено» без места в потоке. Сообщение, которое должно остаться, — `Alert` |
| `ConfirmDialog` | Паттерн «вопрос → пояснение → Отмена \| Действие» поверх `Modal`; фокус на отмене, тон danger только на кнопке | Необратимое действие. Обратимое удерживают возможностью отмены, не модалкой |
| `VisuallyHidden` | Текст только для скринридеров | Иконочный контрол, чей смысл шире короткой подписи |

### shared/ui/Micro — микро-слой

Иерархия системы: **Token → Micro → Component → Pattern → Page**. Микро —
деталь размером с проп: один глиф, одна точка, одна кнопка-пресет. Живёт
ОДНИМ семейным слайсом (как Page и Layout) с публичной точкой
`@/shared/ui/Micro` — одиннадцать папок в корне `shared/ui` стоили бы дороже
самих компонентов. Правило включения и список отвергнутого — в JSDoc слайса.

| Микро | Что это | Брать, когда |
|---|---|---|
| `Kbd` | Хоткей («Ctrl K») тихим текстом, без рамки-кейкапа | Подсказка шортката рядом с действием. Уже рисует `SearchTrigger` |
| `RequiredMark` | Звёздочка обязательности (aria-hidden) | Внутри `<Field>`. Сама по себе не ставится |
| `Dot` | Разделитель метаданных «·» | Ряды вида «автор · дата» внутри `<Inline gap={1}>` |
| `TruncatedText` | Одна строка с многоточием, полный текст в title | Ячейка или подпись, где обрезка неизбежна |
| `NumericText` | Цифры с табличной выравнивкой разрядов | Числа, которые сравнивают глазами: суммы, проценты |
| `Delta` | Стрелка направления + число; цвет подключается тоном ЯВНО | Изменение к предыдущему значению. Семантику («рост = хорошо») называет домен |
| `StatusDot` | Точка 8px цвета тона | Вторичный сигнал рядом с именем/строкой. Статус-значение — `Badge` |
| `AvatarGroup` | Аватары с перекрытием, хвост «+N», кольцо под поверхность | Список лиц рядом с чем-то. Один человек — голый `Avatar` |
| `CopyButton` | Копия значения в буфер, галочка на полторы секунды вместо тоста | Номера, ИНН, ссылки рядом со значением |
| `CloseButton` | Крестик закрытия: `inherit` (на алерте) / `quiet` (на панели) | Гашение сообщения/панели. Удаление данных — через `ConfirmDialog` |
| `MoreButton` | Пресет «⋯» над `IconButton`: панельная поверхность, имя «Ещё» | Меню второстепенных действий строки/карточки |

Композиция важнее размножения: «значение + копирование» — это
`Inline + NumericText + CopyButton`, а не отдельный CopyableText.

## shared/lib — функции без разметки

| Модуль | Что это |
|---|---|
| `cx` | Склейка классов |
| `date` | `isoLocal` (сегодня по МЕСТНОМУ времени), `dmyToIso` / `isoToDmy`, `parseDmy` (отбрасывает 31.02), `shortDate`, `startOfMonth`, `daysUntil` (разница календарных дней, считается в UTC-полночь — иначе перевод часов съедает день), `daysWord` (склонение через `Intl.PluralRules`). Даты сравниваются как ISO-строки — лексикографический порядок совпадает с хронологическим. Самопроверка: `bun src/shared/lib/date.check.ts` |

## entities — знают про домен

| Слайс | Что это |
|---|---|
| `entities/section` | Данные рейла и деревьев разделов: `NAV_TOP`, `contentFor(id)` → `TreeItem[]` — чистая модель, дерево рендерит универсальный `shared/ui/Tree` |
| `entities/workspace` | `useWorkspaceStore`: `activeId` (проекция URL) + `sidebarOpen` |
| `entities/tender` | Строки реестра, `STATUS` (подпись + тон + иконка), `FACETS` для окна фильтров, `applyFilters`, `tenderPath()`, `bidsDue()` (режим срока сбора КП + расшифровка фразой: пять режимов, отсчёт только у открытого тендера). Общий для реестра и карточки: обе страницы читают отсюда, друг друга не импортируют. Самопроверка: `bun src/entities/tender/model/registry.check.ts` |
| `entities/tender` (сравнение) | Только КОНТРАКТ и счёт, ни строки данных: типы `Comparison` / `PositionGroup` / `Contractor` (расценки ЗА ЕДИНИЦУ, пометки ячеек — `marks`: аномалия с причиной, потенциал за единицу, отказ), `BID_STATUS` + `bidStatus()` (незнакомый id даёт нейтральную капсулу, а не падение), `flatten()`, `sumOf` / `groupSum`, `rankBids()` (проценты, суммы, места и тон колонки; неполное КП всегда уходит вниз), `spread()` (разброс от минимума), `analyzeComparison()` (один проход по строке: медиана, разброс с меткой-порогом, минимум среди НЕаномальных при живой конкуренции, вес, максимум потенциала), предикаты фильтров (`PREDICATES`, комбинируются по И) и пресеты (`PRESETS` = четыре оси состояния целиком + `isModifiedView`). Пороги формул — константы (`SPREAD_*`, `DEV_TOLERANCE`, `POTENTIAL_MIN`): фильтр, бейдж и красная цифра делят один порог. Значений по умолчанию у аргументов нет намеренно. Демо-данные — отдельным файлом `comparison.mock.ts`, подмена на API это замена одного импорта. Самопроверка: `bun src/entities/tender/model/comparison.check.ts` |

## features

| Фича | Что это |

Закрытие («Скрыть»/Escape) возвращает фокус на триггер с `preventScroll`. В слайсе карточки два верхнеуровневых блока (`TenderCompare`, `TenderSummary`),
их внутренние компоненты и сегмент `model/` — прокруточная механика и формат
цвета/процентов живут в `.ts`-файлах без разметки.

`TenderCompare` — раздел «Сравнение», композиция таблицы, где шапка каждой
колонки подрядчика это КАРТОЧКА — отдельный компонент `ContractorCard` (имя по
центру, процент заполнения КП, сумма, статус); колонка красится по месту в
ранжире (тон → токен — `model/compareFormat.ts`) и перекрашивается рукой через
`ColumnPainter`, а карточка открывает досье — `DossierModal` на нативном
`<dialog>`. Ради карточки `Table` публикует модификатор `tableCell.card`
— «ячейка целиком отдана своему содержимому», ради нависающих бейджей —
`tableCell.roomy` (резерв паддингом всей колонки). Строки таблицы — тоже
отдельные компоненты: `CompareRow` собирает строку позиции, `SpreadCell` —
колонка разброса, `BidCell` — ячейка КП со всеми пометками, `TotalRow` — и
подытог раздела, и итог по срезу. Над таблицей —
`CompareToolbar`: пресеты сегментом (`Segmented`), показатель и вид строк —
тихими дропдаунами, предикаты — одним триггером «Фильтры» с поповером и
каунтером; чип «Изменён · Сброс» встаёт рядом с сегментом, когда состояние
ушло от базы пресета; глифы пометок живут в `ui/assets/` (барел `index.ts`),
легенда словаря — `CompareLegend`: тихая кнопка-книга в хвосте полосы,
`<Popover>` со столбиком «образец · название · пояснение», образцы — те же
глифы из ассетов. Пометки ячеек (минимум-бирка, монета запаса торга,
ключ, штриховка аномалии, микрошкала разброса, пунктир пробела, капсула
отказа) рисуют `assets/` + `TenderCompare.module.css`; объясняет их один
попап `useCellPopup()` на всю таблицу. Липкая шапка, автосайдбар и доскролл
к строке из «Анализа» — хук `model/useTableDock.ts`. Стили таблицы — ОДИН
модуль на всё семейство (`TenderCompare.module.css`): правила сцеплены
составными селекторами (`.card:hover .star`, `.group-toggle:has(.fold:hover)`),
а классы хэшируются помодульно — границы компонентов и границы стилей тут не
совпадают намеренно; у досье и палитры свои модули, общих селекторов с
таблицей у них нет. Разбор решений — Часть XII `DESIGN-NOTES.md`.

Второй локальный верхнеуровневый — `TenderSummary`: шапка со сводкой тендера —
название с капсулой статуса справа, под ними карточка с четырьмя полями в сетке
2×2 (заполнение по столбцам: 1 3 / 2 4). Капсула статуса в покое схлопнута до
глифа и разъезжается под курсором — это рецепт 10 каталога состояний, применённый
здесь единственный раз. Значения полей готовились под инлайновый ввод
(поверхность общая — `.inline-edit` в `global.css`), но редактирование выключено
до появления сохранения: поля пока читаются текстом. Строка поля и подсказка на
`::after` (`data-hint` + `<VisuallyHidden>` для скринридера)
остаются локальными: выносить в `shared` есть смысл со второго потребителя, не
раньше — доменного знания в строке ровно на подбор полей, а `<Tooltip>` без
второго вызова примитив, спроектированный вслепую.

Локально в слайсе реестра остался ровно один компонент — `RegistryFilters`:
полоса фильтров. Она композиция общих примитивов плюс раскладка полосы и
индикаторы поверх кнопок без подписи; всё остальное (окно фильтров, календарь,
строка мультивыбора, поле поиска, кнопки) уехало в `shared/ui`.

## Состояния: одна шкала на всё

Токены в `src/app/styles/global.css`, там же **каталог из десяти рецептов
взаимодействия** — закрытый список того, как элемент отвечает на курсор и фокус.
Десятый (раскрытие подписи под курсором, `0fr → 1fr`) — единственное
разрешённое изменение размера под курсором, и разрешено оно тремя условиями
сразу: элемент не кликабельный, справа от него в потоке пусто, скрытая подпись
— третий канал, а не единственный. Применён один раз, в капсуле статуса
`TenderSummary`.

| Токен | Значение | Когда |
|---|---|---|
| `--cu-state-hover-subtle` | `rgba(0,0,0,.05)` | Крупная поверхность: строка списка, пункт меню, строка таблицы |
| `--cu-state-hover` | `rgba(0,0,0,.06)` | Компактный контрол 22–32px; он же — текущее состояние строки |
| `--cu-state-hover-strong` | `rgba(0,0,0,.09)` | Контрол, у которого в покое уже есть заливка (`Button on`, `IconButton active`) |
| `--cu-state-ring` | `0 0 0 1px rgba(0,0,0,.16)` | Белая капсула на светлом фоне — заливать нечем |
| `--cu-focus-ring` | `2px solid rgba(0,0,0,.25)` | Фокус с клавиатуры |
| `--cu-fill` / `--cu-fill-subtle` | `.06` / `.035` | Заливка в покое |

Ступень выбирается по двум правилам, а не «как у соседнего компонента»:
**площадь обратно пропорциональна плотности** (большой поверхности хватает более
слабой заливки) и **контрол с собственной заливкой шагает вверх** (иначе hover
не читается поверх своего же фона).

### Семантические тона

Живут в токенах `--cu-tone-*` (`global.css`), а не по месту: потребителей
четверо — `Badge` в таблице, `MenuCheckItem` в фильтре и его круглый значок,
плюс колонка подрядчика в сравнении КП (заливка `color-mix` в 7% и полоска
карточки).

| Тон | `--cu-tone-*` | `-ink` (текст поверх заливки) | `-fill` (.1) |
|---|---|---|---|
| info | `rgb(29,110,220)` | `rgb(24,88,176)` | `rgba(29,110,220,.1)` |
| success | `rgb(0,138,86)` | `rgb(0,116,72)` | `rgba(0,138,86,.1)` |
| warning | `rgb(214,119,10)` | `rgb(176,96,6)` | `rgba(214,119,10,.1)` |
| danger | `rgb(233,61,130)` | `rgb(197,40,105)` | `rgba(233,61,130,.1)` |
| neutral | `rgb(150,150,150)` | secondary | `--cu-fill` |

`warning` появился вместе со сравнением КП: у ранжира три деления — «лучшее /
среднее / худшее», и среднему в шкале info/success/danger места не было.

Три роли путать нельзя: сам цвет (точка, значок, залитый чекбокс), `ink` (текст
на подложке — исходный цвет на своей же заливке не добирает контраста) и `fill`
(тихая подложка). Нейтральный намеренно не цветной: «черновик» — отсутствие
состояния.

Тип `Tone` экспортирует `shared/ui/Badge`; доменные таблицы статусов
типизируются им, чтобы не заводить своей палитры. Правило: **одно состояние —
один тон и один глиф во всех местах сразу**, и то и другое описано ОДИН раз
(`STATUS` в `entities/tender`).

### Типографика и движение: те же токены

Вместе со слоем дизайн-системы в `global.css` появились две новые именованные
шкалы; обе НИЧЕГО не меняют визуально — они называют то, что уже было.

| Токен | Значения | Когда |
|---|---|---|
| `--cu-text-xs…2xl` | 11 / 12 / 13 / 14 / 16 / 18 / 20 px | Кегль по роли; каждая ступень снята с живых модулей, новая сетка НЕ вводилась |
| `--cu-leading-{same,tight,normal}` | 1 / 1.15 / 1.4 | Безразмерные множители: сами дают верную пару для любого кегля шкалы |
| `--cu-duration-{fast,base,slow}` | .12s / .2s / .28s | Микрореакция контрола / стандартная реакция каталога состояний / выезжающая панель |
| `--cu-ease-{standard,enter,exit,emphasized}` | две кривые | standard — состояния; emphasized — панели, чей выезд виден целиком |

Старые имена `--cu-animation-*` и `--flyout-*` остались КАК ССЫЛКИ на новую
шкалу: модули каркаса не тронуты, источник значения теперь один.

Шкала расстояний отдельно НЕ заводилась: ею уже была лестница `--cu-size-N`
(4…36px) из эталона. В коде она типизирована слайсом `Layout`
(`GapIndex`: `gap={3}`, а не пиксели).

Глобальное правило `prefers-reduced-motion` гасит ВСЕ переходы и анимации до
одного кадра: отключается движение, а не информация — тот же принцип, что у
рецепта 10 каталога, поднятый на приложение.

## Что осталось нерешённым

- **Две тёмные кнопки**: `ChipButton` (28px, шапка страницы — число из эталона)
  и `Button variant="primary"` (32px, панельная шкала). Слить нельзя, не сдвинув
  пиксели; у `ChipButton` и `PageActions` сейчас НЕТ ни одного потребителя —
  они ждут возвращения экрана с действиями в шапке.
- **Радиусы не следуют размеру**: 28px → 7px, 32px → 6px, 22px → 5px, 32px на
  рейле → 8px. Поэтому `IconButton` кодирует поверхность вариантом, а не парой
  `size`+`radius`. Унификация изменит пиксели — нужно отдельное решение.
- **`:focus-visible` есть не у всех**: добавлен у `IconButton`, `Button`,
  `MenuItem`, `MenuCheckItem`, `SearchInput`, дней календаря, строк дерева и
  тоггла; у крошек, пунктов рейла и переключателя воркспейса — пока нет.
- **Клавиатура в меню**: стрелки/Home/End и ArrowDown-на-триггере сделаны в
  `<Dropdown>` (roving tabindex, Escape возвращает фокус); пункты — `<button>`,
  так что Enter/Space жмут их сами. Роли radio/checkbox объявляют
  `MenuItem checked` и `MenuCheckItem`.
- **`Breadcrumbs` завязан на react-router** (`<Link>`). Осознанно: реюз внутри
  этого приложения. Для выноса в пакет понадобится проп `renderLink`.
- **`Table` не умеет сортировку и выбор строк**: сейчас это геометрия + палитра
  и ничего больше. Появятся — добавлять в примитив, а не в страницу.
- **`FacetFilter` не виртуализирован**: потолок в 50 строк вместо этого. До
  списков, где потолок начнёт мешать, вопрос не стоит.
- **Фильтры не сохраняются**: состояние живёт в `useState` страницы, в URL его
  нет. Значит, ссылку на отфильтрованный реестр не отправить и F5 её сбрасывает.
- **Избранное и цвет колонки в сравнении КП — тоже `useState` страницы**: та же
  цена, что у фильтров, и по той же причине (сервера нет). Отметка «в
  избранном» пока ничего не делает, кроме того что видна.
- **Черновик вопроса в панели «Анализ» умирает с уходом на другой тендер**:
  док смонтирован всегда, поэтому переключение вкладок карточки черновик
  переживает; состояние открытости и срез сравнения в URL не попадают — та же
  мебель, что вкладки и фильтры.
- **`<Modal>` и `<Popover>` не умеют вложенности**: панель, открытая из окна,
  попадёт в тот же верхний слой и закроется вместе с ним. Случая пока нет;
  появится — это про `closedby` и стек, а не про третий `<dialog>`.
- **Контракт ширины колонок живёт в модуле `TenderCompare`**, хотя доменного в
  нём ничего нет: `<Table layout="fixed">` даёт режим, а сама формула (пол,
  потолок, равная доля, остаток названию) — на странице. Обобщать пришлось бы
  не числа, а РОЛИ колонок; со вторым таким экраном это `tableCol` рядом с
  `tableCell`, тем же приёмом. Разбор — Часть XII `DESIGN-NOTES.md`.
- **`Select` использует грамматику меню** (`menu`/`menuitemradio`), а не
  listbox: клавиатура и Escape уже сделаны в `Dropdown`, вторая механика
  дала бы два места правки одного поведения. Вернуться к вопросу стоит,
  когда появится список с поиском по буквам (typeahead).
- **`Tooltip` живёт вне верхнего слоя**: он `position:fixed` в портале, поэтому
  внутри transformed-предка спозиционируется неверно. Случай появится —
  переезд на `<dialog>` или CSS anchor positioning; тяжёлый сценарий (ячейки
  таблицы) уже закрыт `CellPopup`.
- **Тосты НЕ показываются поверх открытых окон**: верхний слой у
  `<dialog>` всегда выше любого z-index. Осознанно: сообщение поверх подложки
  читалось бы как паника.
- **Новые компоненты пока без потребителей в экранах**: слой собран как
  библиотека поверх существующих решений, страницы сознательно НЕ переводились
  на него (пиксели каркаса и продуктовых экранов не тронуты). Первые
  потребители придут со следующими экранами; при переносе старых — сверяться
  с Частью XIII `DESIGN-NOTES.md`.
