# Аудит папки `ai_audit/` — история и устройство блока «ИИ-анализ»

В папке лежат три HTML-файла — это **три поколения одного и того же экрана**
(«Сравнение КП» тендера T-2026-014) с блоком «Анализ» справа. Все три —
статические макеты без бэкенда: никаких реальных вызовов ИИ нет, весь
«интеллект» — предвычисленные флаги данных и заготовленные тексты.

---

## 1. Три файла = три эпохи одного экрана

| Файл | Что это | Технология |
|---|---|---|
| `tender-comparison-full.html` | **v1 — исходный прототип.** Полный статичный макет экрана сравнения КП. Комментарий в шапке: «Для Mark/Kirill: крутить пресеты, цвета, колонки, анализ-панель без бэкенда». Деплоился на `tertysh.ru/c/aag/demo/` | Чистый HTML + vanilla JS, инлайновый рендер через `innerHTML`, дизайн-токены в `:root`, системный шрифт |
| `Сравнение КП.dc.html` | **v2 — перенос в формат `.dc`.** Тот же экран, переработанный визуально (шрифты IBM Plex Sans/Mono, палитра oklch) и расширенный: редактируемая шапка тендера, блок бюджетной позиции (БП), вид «Решение» с протоколом выбора | Формат дизайн-компонента: `<x-dc>`, класс `Component extends DCLogic`, `renderVals()` возвращает значения для `{{ плейсхолдеров }}`, `sc-if`/`sc-for` — условие/цикл шаблонизатора, `data-props` — метаданные пропсов для редактора (`density`, `showMinBadge`, `dockDefaultOpen`) |
| `Страница тендера · Снабли.dc.html` | **v3 — интеграция в продукт «Снабли».** Экран встроен в продуктовую оболочку: бренд, breadcrumbs, дизайн-система `DesignSystem_6e248e` (`Button`, `Menu`, `Badge`, `Tabs`, `Segmented`, `EntityHeader`, `Textarea`, `Alert`). Добавлены вкладка «Контрагенты» и кнопка «К решению» | Тот же `.dc`, но вместо сырой разметки — импорт компонентов ДС через `<x-import component-from-global-scope=…>` |

Направление эволюции: свободный макет → самостоятельный компонент в новом
визуальном языке → страница внутри дизайн-системы продукта. Модель данных при
этом почти не менялась — она сложилась уже в v1 (см. ниже).

## 2. Модель данных, на которой держится анализ

Во всех трёх файлах одинаковый набор констант (в v1/v3 совпадают дословно):

- **`SUPPLIERS` / `SUP`** — 3 подрядчика: АО «МетСнаб» (11 840 000 ₽,
  покрытие 100%), ООО «ИнженерГрупп» (12 156 000 ₽, 95%), ООО «СтройМонтаж»
  (11 980 000 ₽, 88%). У каждого цвет (для точек и «полоски разброса»),
  версия КП, а в v3 ещё ИНН/контакты, срок, оплата, статус и список версий КП.
- **`ITEMS`** — 20 позиций сметы в 4 разделах (Материалы, СМР/Фундамент,
  СМР/Каркас, Прочее). На каждую позицию — `cells[supplierId]`:
  - `price` — цена поставщика;
  - `deviation` — отклонение от лучшей цены, %;
  - `potential` — «потенциал торга»: сколько можно сэкономить, если сбить
    цену этого поставщика до минимальной по позиции;
  - `isMin` — минимальная цена по строке (подсвечивается);
  - `anomaly` — аномальная цена (в срезе их 3: арматура −6,4% у
    СтройМонтажа, деформационные швы +9,8%, анкеровка +12,8%);
  - `missing` — цены нет («Прогрев бетона» у МетСнаб).
  Плюс флаги строки: `isKey` (ключевая), `spreadTag`
  (`none`/`noticeable`/`high` — разброс цен), `removed` (позиция снята),
  `corrected` (кол-во скорректировано), `declined` (отказ поставщика).
- **`PRESETS`** — пресеты вида таблицы: `overview` (Обзор), `bidding`
  (Торги: показатель «потенциал», сортировка по потенциалу, фильтр
  «есть потенциал»), `anomalies` (Аномалии: показатель «отклонение»,
  сортировка по весу, фильтр «аномалии»).
- **`FILTERS`** — чипсы: Ключевые / Высокий разброс / Аномалии /
  Есть потенциал (в v1 ещё «Выше медианы»).
- **`PAIR` / `PAIR_DIFF`** — вклад позиций в разницу между двумя
  избранными ★ подрядчиками (фундамент −276 тыс., бетон −126 тыс., …),
  с долей каждой позиции.
- **`SCENARIOS`** — 5 сценариев анализа (см. раздел 3).
- **`INSIGHTS`** — тексты карточек анализа, сгруппированные по сценариям;
  каждая ссылается на строку таблицы (`row: itemId`).
- **`BP`** (v2/v3) — бюджетные позиции с лимитом и уже размещённой суммой;
  на них считается полоса «Расход лимита» и алерт перерасхода.

Производные величины считаются на лету helpers'ами: `prices()` (валидные
цены строки), разброс `((max−min)/min·100)%`, `weight()` (максимальная цена
строки = «вес»), `maxPot()`, `hasAnomaly()`, `hasPotential()`, ранги
поставщиков, число позиций min, суммарный потенциал торга по срезу.

## 3. Блок «ИИ-анализ» (док «Анализ»)

### 3.1 Смысл блока

Док справа от таблицы сравнения — это слой **интерпретации поверх сырой
таблицы**: он отвечает не «какие цены», а «что с этим делать» — где торговаться,
что проверить, кто рискованный. Подзаголовок во всех версиях честно это
обозначает: **«правила + ИИ по КП раунда 1»**. Расшифровка деления:

- **Правила** — детерминированные находки из данных: аномалия по отклонению,
  отсутствие цены, высокий разброс, крупный потенциал, вклад в разницу пары.
  В макетах они захардкожены в `INSIGHTS`, но структура («карточка = правило =
  ссылка на строку») именно такая.
- **«ИИ»** — свободный вопрос пользователя («Спросить ИИ») и связывание
  находок в рекомендации (протокол выбора). В макете ответ генерируется
  шаблонной строкой из текущего состояния — демо-заглушка под будущий LLM-вызов.

### 3.2 Состав дока (общий для всех трёх файлов)

1. **Шапка дока**: заголовок «✦ Анализ», подзаголовок «по КП раунда 1 ·
   правила + ИИ», кнопка закрытия ✕. Открытие/закрытие — кнопкой «Анализ» в
   топбаре (`toggleDock`); сетка контента перестраивается
   (`grid-template-columns: minmax(0,1fr) 340–360px`). В `.dc`-версиях
   начальное состояние задаётся пропом `dockDefaultOpen`.
2. **Чипсы сценариев** (`SCENARIOS`, 5 штук):
   - **Что важно** (`important`) — главные факты среза;
   - **Точки торгов** (`bidding`) — где есть потенциал сбить цену;
   - **Сравнить подрядчиков** (`compare`) — итог по отмеченной паре ★;
   - **Риски и аномалии** (`anomalies`) — что требует обоснования;
   - **Выбранное ★** (`selection`) — сводка по избранному.
   Особое поведение: выбор сценариев `bidding` и `anomalies` **заодно
   переключает пресет таблицы** (показатель, сортировку строк, фильтры) —
   анализ синхронизирован со срезом данных. Остальные сценарии меняют только
   набор карточек.
3. **Карточки инсайтов** (`INSIGHTS[scenario]`): тег (факт / торг / риск —
   типы `info` / `trade` / `risk`), заголовок, текст, мета «правило ·
   <сценарий>». Цветовое кодирование: левая цветная плашка/бейдж по тегу
   (v1 — бордер слева, v2 — бордер + моно-тег, v3 — `Badge` с тоном
   `neutral`/`amber`/`danger`).
   **Клик по карточке = переход к данным**: `focusRow(i.row)` подсвечивает
   соответствующую строку таблицы (фон фокуса) и скроллит к ней, плюс тост
   «Строка подсвечена по карточке анализа». Это ключевая механика блока:
   анализ не оторван от таблицы, каждая мысль кликабельна до конкретной позиции.
4. **«Спросить ИИ»**: textarea (плейсхолдеры: «Свой вопрос по выделенным ★ или
   сценарию…» / «Вопрос по отмеченным ★ или сценарию…») + кнопка «Спросить».
   Логика ответа (`runAsk`) одинакова во всех версиях:
   - вопрос по умолчанию, если поле пусто: «Где выгоднее и где риски по
     избранным ★»;
   - если отмечены **два** ★ — возвращается заготовленная выжимка: «МетСнаб
     против ИнженерГрупп: МетСнаб дешевле на 316 тыс. ₽, основной вклад —
     фундамент и бетон. Проверьте прогрев у МетСнаб (нет цены) и аномалии
     СтройМонтажа»;
   - иначе — просьба отметить двух подрядчиков с перечислением текущего выбора.
   Ответ помечен как «Ответ · демо». То есть даже в макете заложена логика:
   ответ ИИ зависит от контекста (пара ★ + вопрос).
5. Только в v1: инфо-баннер «Статичный вывод правил и „ИИ“. Клик по карточке
   подсвечивает строку в таблице» и декоративные чипсы истории запросов
   («12.07 · Что важно», «11.07 · Торги»). В v2/v3 от них отказались.

### 3.3 Содержимое карточек (одинаково во всех трёх файлах)

- *Что важно*: «Фундамент и бетон — 62% суммы» (факт, строка 7);
  «Прогрев не закрыт у МетСнаб» (риск, строка 18).
- *Точки торгов*: «Потенциал ~273 тыс. на фундаменте» (торг, 7);
  «Генподряд — точка торга» (торг, 20).
- *Сравнить подрядчиков*: «МетСнаб против ИнженерГрупп: −316 тыс.» (факт, 7).
- *Риски и аномалии*: «3 аномалии в срезе… Запросить обоснование» (риск, 2);
  «Высокий разброс: 4 позиции» (риск, 10).
- *Выбранное ★*: «Пара ★: МетСнаб + ИнженерГрупп» (факт, 7).

Каждая карточка — это фактически вывод правила над `ITEMS`: агрегат по весу
позиций, проверка `missing`, подсчёт `anomaly`, разница пары из `PAIR`.

## 4. Функционал вокруг анализа (тот же экран)

Чтобы понимать контекст, в который встроен док:

- **Таблица сравнения**: строки-позиции × колонки-поставщики; sticky-шапка и
  sticky первая колонка, липкая строка «Итого»; разделы сворачиваются, вид
  строк — Разделы / По весу / По потенциалу; главный показатель ячейки —
  Цена / Откл. / Потенциал (+ доп. показатели второй строкой); бейджи
  (ключ / аном. / корр. / снята), метка MIN, красный рельс у аномальной
  ячейки, «нет цены» / «отказ»; «полоска разброса» с точками поставщиков.
- **Разница КП** (pair diff): появляется при ровно двух ★; итоговая разница +
  вклад позиций с долями; клик по строке — фокус в таблице. Ограничение
  «ровно два ★» защищено тостом («Для разницы КП нужно ровно две ★…»).
- **Шапка тендера** (v2/v3): редактируемые название/объект/ответственный/
  срок/статус/бюджет; блок «Расход лимита» бюджетной позиции — полоса
  «уже размещено / этот тендер / лимит», % лимита, при перерасходе — красная
  заливка и `Alert` с вариантами действий.
- **Вкладка «Контрагенты»** (только v3): карточки поставщиков с покрытием,
  числом позиций min, пробелами и аномалиями, версиями КП (v1/v2, «ожидаем»),
  риск-заметкой и действиями (★ в пару, запросить уточнение, открыть в
  сравнении); кнопки «Пригласить подрядчика», «Запросить раунд 2».
- **Вид «Решение»** (v2/v3): радио-карточки поставщиков с рангом по цене,
  метриками (покрытие, к бюджету, позиций min, потенциал торга, риски) и
  вердиктом-заметкой; справа — черновик «Протокол выбора», который собирается
  из текущего победителя и бюджета (рекомендация + шаги: запросить обоснование
  по аномалиям, закрыть прогрев, провести раунд 2). Протокол — прямой
  потребитель выводов анализа.

## 5. Чем блок анализа отличается между версиями

| Аспект | v1 (`tender-comparison-full`) | v2 (`Сравнение КП.dc`) | v3 (`Страница тендера · Снабли.dc`) |
|---|---|---|---|
| Размещение | Отдельный `<aside>` в grid, скрытие через `hidden` + класс | `<sc-if value="{{ dockOpen }}">` в сетке | То же, колонка 360px; кнопка «Анализ» в топбаре меняет variant (`soft`/`ghost`) |
| Инфо-баннер «это статика» | Есть | Нет | Нет |
| История запросов (чипсы) | Есть (декоративные) | Нет | Нет |
| Сценарии→пресеты | Да (bidding/anomalies) | Да | Да |
| Оформление карточек | Бордер слева по тегу, мета «правило · …» | Бордер + моно-тег «факт/торг/риск», мета | `Badge` с тоном, без меты |
| Ссылка карточки→строка | Захардкоженная карта `{0:7, 1:18, 2:1}` | Из данных (`i.row`) | Из данных (`i.row`) |
| «Спросить ИИ» | textarea + кнопка, ответ в `.ask-result` | То же, стилизовано ДС-элементами | `Textarea` + `Button variant="primary"` ДС |

То есть содержательно блок сложился уже в v1; v2/v3 — только переупаковка в
новую систему оформления и мелкие чистки.

## 6. Наблюдения и артефакты

1. **«ИИ» в макетах — имитация.** Ни одного сетевого вызова нет; `runAsk`
   возвращает шаблонную строку. Для продакшена точек интеграции две: замена
   `INSIGHTS` на серверный расчёт правил и `runAsk` на LLM с контекстом
   (срез таблицы + пара ★ + вопрос).
2. **Связка «анализ ↔ таблица» продумана хорошо**: сценарий переключает
   пресет среза, карточка подсвечивает строку, пара ★ кормит и «Разницу КП»,
   и ответ «Спросить ИИ», и протокол решения. Это стоит сохранить при переносе
   в React-приложение.
3. **В файле v3 есть следы повреждения текста** (вероятно, артефакт
   копипасты/экспорта): ломаная разметка в строке 89–90 (атрибуты `style`
   слиплись с содержимым), мусорные фрагменты `</button></sc-if>` около строк
   168–174, перепутанные слова в данных — «Отказ по обратной засыпке пазух —
   потребуется отдельный подряд» (п. 9, `risk`) и искажённое имя позиции
   «Монтаж опалубки» (id 12). В v1/v2 эти же данные корректны. Если файл v3
   будет использоваться как эталон — эти места надо править по v2.
4. В v1 фильтр «Выше медианы» объявлен в `FILTER_LABELS`, но в рендере
   контролов не используется (мёртвая опция); в v2/v3 его уже нет.
5. Файлы v2/v3 ссылаются на `./support.js` и ассеты `_ds/…`, которых в папке
   нет — сами по себе в браузере они полноценно не откроются (это экспорты
   дизайн-инструмента, рассчитанные на его окружение).
