# «Призма» — ТЗ на блок ИИ-анализа карточки тендера

> Кодовое имя «Призма»: три КП входят, спектр находок выходит. В интерфейсе
> слово «Призма» не звучит ни разу — оно про суть, а не про копирайт.

Источники функционала — три прототипа из этой папки
(`tender-comparison-full.html`, `Сравнение КП.dc.html`,
`Страница тендера · Снабли.dc.html`): док «Анализ» переносится целиком,
без сокращений. Решения по форме приняты по скиллам `design` →
`product-design` + `ui-animation` + `frontend-design` поверх ядра проекта
(токены `--cu-*`, каталог десяти рецептов, шкала движения в `global.css`).

---

## 0. Одной фразой

В правом краю строки названия тендера живёт **искра** — единственное
переливающееся пятно дисциплинированного монохромного интерфейса; клик по ней
выдвигает справа **немодальную панель «Анализ»**, которая дублирует весь
функционал прототипов: пять сценариев, карточки правил, подсветку строк
таблицы по клику и свободный вопрос к ИИ.

Почему это уместно именно здесь: прототипы проверили главное — анализ работает,
когда он **рядом с данными и кликается в данные**. Карточка правила без строки
таблицы — мнение; карточка, которая подсвечивает строку, — инструмент.

---

## 1. Право на цвет (креативное обоснование)

Интерфейс проекта монохромен намеренно: серая шкала отвечает «насколько
важно», пять тонов `--cu-tone-*` — «что это значит». Радуга в такой системе —
не украшение, а **крик**: цвет, который не значит ничего из уже названного.

Искра переливается потому, что означает ровно одно: *за этим — поведение,
которое не выведено из данных детерминированно*. Все остальные цвета экрана
читаются как факты; этот — как вопрос к машине. Это единственный элемент
продукта, которому разрешено мерцать, и потому он читается мгновенно.

**Спектр собирается из собственных тонов проекта, а не с потолка:**

| Стоп | Значение | Происхождение |
|---|---|---|
| A | `rgb(29,110,220)` | существующий `--cu-tone-info` |
| B | `rgb(124,58,237)` | новая ступень — фиолетовый, середина между A и C |
| C | `rgb(197,40,105)` | существующий `--cu-tone-danger-ink` |

Токены заводятся одним семейством в `global.css` рядом с тонами:
`--cu-ai-a`, `--cu-ai-b`, `--cu-ai-c`. Это **не** новый `--cu-tone-ai`:
тон — это смысл состояния, а у ИИ состояний нет, есть принадлежность к
системе. Семейство из трёх стопов — палитра глифа, не семантика.

## 2. Искра: анатомия кнопки

### 2.1 Место

Строка названия тендера — `.summary__head` в `TenderSummary`: сегодня там
`[h1][капсула статуса]`. Кнопка встаёт в **правый край той же строки**
(см. § 3 про конфликт с рецептом 10 — он разрешён, и не в пользу капсулы).

Триада строки: *что открыто* (название) → *в каком состоянии* (статус) →
*кто поможет решить* (искра). Искра — крайняя справа точка контентной колонки:
та же вертикаль 12px, зеркальная левой.

### 2.2 Геометрия (посчитана, не на глазана)

Кнопка — 28×28, радиус 7px (шкала из `COMPONENTS.md`: 28px → 7px), анатомия
`IconButton variant="topbar"`: та же заливка-таблетка по наведению (рецепт 1),
то же кольцо фокуса (рецепт 9). Локальная копия, а не сам `IconButton`: внутрь
идёт анимированный SVG, а не глиф из карты `Icon`; при втором потребителе —
научить `IconButton` принимать детей, но раньше второго потребителя этого не
делать (правило «со второго потребителя», как `Field` в сводке).

Глиф — четырёхлучевая искра, viewBox `0 0 16 16`, центр C=(8,8):

- большие лучи R = 7: острия (8,1), (15,8), (8,15), (1,8);
- перпендикулярный отступ рёбер k = 0.05·R ≈ 0.35 — контрольные точки кубик
  кривых сидят на середине полуребра, смещённые наружу от оси на k;
  это даёт вогнутое пламя без «подушки»;

```
M 8 1
C 8.34 5.06 10.94 7.66 15 8
C 10.94 8.34 8.34 10.94 8 15
C 7.66 10.94 5.06 8.34 1 8
C 5.06 7.66 7.66 5.06 8 1 Z
```

Путь симметричен поворотом на 90° — проверяется подстановкой. Внутри искры —
две линии-«грани» из центра в противоположные доли (stroke 1, opacity .25):
намёк на призму, тот самый смысл из шапки документа. При рендере мельче 20px
грани скрываются (`@media` не нужен — просто отдельный проп/класс мелкого
употребления, если появится).

Все градиентные id внутри SVG — через `useId()`: клип-пути хэшируются
помодульно так же, как классы CSS, два экземпляра на странице не имеют права
делить `url(#…)`.

### 2.3 Переливание: механика

Один приём, без библиотек: поверх заливки искры крутится **градиентный мазок**,
обрезанный клип-путём глифа.

```svg
<svg viewBox="0 0 16 16">
  <defs>
    <linearGradient id={gid}>…стопы A → B → C → A…</linearGradient>
    <clipPath id={cid}><path d="{искра}"/></clipPath>
  </defs>
  <g clipPath={`url(#${cid})`}>
    <rect class="sheen" x="-12" y="-12" width="40" height="40"
          fill={`url(#${gid})`}/>
  </g>
</svg>
```

```css
.sheen {
  transform-origin: center;
  transform-box: fill-box;
  animation: ai-spin 6s linear infinite;
}
@keyframes ai-spin { to { transform: rotate(360deg); }
```

Выбор реализации по правилам `ui-animation`:

- постоянное движение → easing `linear` (6 s период — ниже порога заметности,
  искра «дышит», а не мигает);
- движение только `transform: rotate` — композитор, без layout и paint;
- **CSS-animation, не SMIL**: глобальный кламп
  `@media (prefers-reduced-motion: reduce)` в `global.css` гасит длительности
  CSS-анимаций до кадра — искра автоматически становится статичным
  градиентом без единой строчки нового кода. SMIL так не умеет;
- пауза вне экрана: `IntersectionObserver` снимает класс анимации, когда
  строка названия ушла из вида; то же при `document.hidden`
  (правило «зацикленные анимации паузятся вне экрана»);
- id-градиент общий на все экземпляры кнопки не обязателен, но период
  вращения у всех синхронный — две искры на экране не должны дышать вразнобой.

### 2.4 Состояния кнопки (скорость = состояние машины)

Это сигнатура блока: **темп переливания — язык состояния ИИ**, других
индикаторов загрузки в панели не нужно.

| Состояние | Когда | Глиф | Поверхность |
|---|---|---|---|
| покой | док закрыт, ответов не ждём | 6 s / оборот | прозрачная |
| наведение | hover / focus-visible | 3 s — разгоняется, откликаясь | рецепт 1, ступень `--cu-state-hover` |
| открыто | док открыт | стоп-кадр (угол ≈ 40°) | рецепт 2 — текущее состояние, `--cu-state-hover-strong` |
| думает | запрос отправлен, стрим идёт | 0.9 s — быстрое мерцание | без изменений |
| сбой | ошибка ответа | стоп + `filter: saturate(0)` | без изменений |

Наведение меняет темп плавно (`animation-duration` не транзишенится — скачок
периода маскируется самим движением; проверять на резкость при медленном
проигрывании). Никакого scale и сдвига кнопки: каталог запрещает изменение
размера под курсором, нажатие показывается ступенью заливки `:active`
(`--cu-state-hover-strong`).

Доступное имя: `aria-label="ИИ-анализ тендера"`, `aria-expanded`,
`aria-controls` на id панели (правило `rule/accessible-name-required`).

## 3. Конфликт с рецептом 10 и его разрешение

Капсула статуса в этой же строке раскрывается по наведению (0fr → 1fr),
и её второй законной условия — «справа в потоке ничего нет». Любая кнопка,
поставленная в поток правее капсулы, превращается в уезжающую цель: раскрытие
подписи сдвинет её на ширину слова «Открыт». Каталог прям: не выполнено хотя
бы одно условие — рецепт не подходит. Отказываться от раскрывающейся капсулы
или от места кнопки нельзя — зафиксированы оба решения.

Разрешение: **кнопка не в потоке**. `.summary__head` получает
`position: relative`, кнопка — `position: absolute; right: 0; top: 50%;
translateY(-50%)`. Изъятая из потока, она не участвует в раскладке: раскрытие
капсулы продолжало есть пустоту справа от себя, как сегодня, глиф капсулы
остаётся неподвижным под курсором, кнопка стоит на месте всегда.

Цена приёма — поведение при переносе строк (`flex-wrap` на узком `<main>`:
капсула падает под название). На узких контейнерах (container query
`@container (max-width: 560px)` на обёртке страницы — `.table-wrap` уже
приучил проект к `cqw`) кнопка возвращается в поток последним элементом
строки: absolute-режим выключается тем же запросом. Одна пара правил, обе
ветки описаны здесь, магических чисел нет.

Бонус позиционирования: панель (§ 4) визуально выдвигается из-под кнопки при
любой ширине названия — пространственная связь «нажал здесь — приехало сюда»
не зависит от того, сколько слов в тендере.

## 4. Панель: размещение, движение, слои

### 4.1 Оверлей, а не сжатие сетки

Прототипы вдвигают док в grid и сжимают таблицу (`grid-template-columns`).
Здесь принято другое решение: панель — **немодальный оверлей** у правого края
рабочей области, содержимое не двигается вовсе.

Причины. Таблица сравнения живёт в `layout="fixed"` с минимальной шириной
1140px+: любое сжатие колонки сразу конвертируется в горизонтальный скролл —
прототипы платили этим же. Анимировать `grid-template-columns` — анимировать
layout (запрещено правилами движения; исключение «сознательный container
tween» тут не оправдано, ценой будет дёргающийся рефлоу всей таблицы каждый
кадр). Оверлей двигается чистым `transform`, таблица продолжает жить под ним:
карточка правила подсвечивает строку, строка видна рядом — рабочий сценарий
блока не ломается.

Форма: фиксированная ширина **400px** (`--ai-dock-width`, токен фичи),
высота — вся рабочая область правее рейла и ниже топбара; правый край
совпадает с краем контента. Поверхность `--cu-background-main`, левая кромка —
`box-shadow: var(--cu-elevation-border-4)`: хэйрлайн + подъём, как у меню —
панель читается висящей над страницей.

Слой: новый токен `--z-dock: 900` в лестнице `global.css` — над sticky-шапкой
таблицы, под рейлом (999), топбаром (1200), меню и тостами. Подложки нет:
панель немодальна, страница остаётся интерактивной
(`rule/inline-before-modal` — раскрытие рядом с работой, а не отрыв от неё).

### 4.2 Движение

Из токенов проекта, без новых кривых. `--cu-duration-slow` (.28s) прямо
документирован как время панелей, которые выезжают; `--cu-ease-emphasized` —
«резкий старт и мягкая посадка для панелей, чьё движение видно целиком».
Проект важнее дефолтов скилла, поэтому не 400ms из рецептов, а родная шкала:

| Такт | Свойства | Время / кривая |
|---|---|---|
| открыть | `transform: translateX(100% → 0)` | .28 s / emphasized |
| закрыть | тот же путь обратно | .28 s / emphasized |
| содержимое | появляется ВМЕСТЕ с панелью, без собственного стагтера | — |

Антипаттерн «панель едет, дети догоняют» не воспроизводится: контент уже на
месте к моменту прибытия. Закрытие — тем же путём (enter/exit в проекте пока
совпадают). Быстрые двойные клики переживаются штатно: transition ретаргетится,
keyframes не используются. `prefers-reduced-motion` гасится глобальным
клампом, панель просто появляется.

Фокус и клавиатура (`rule/keyboard-complete-flow`): открытие переводит фокус
на заголовок панели (`tabindex="-1"`), Escape закрывает панель, когда фокус
внутри неё (обработчик на самой панели — немодальный конвеншн, страница
своих Escape-обработчиков не получает), закрытие возвращает фокус на кнопку.
Ловушка фокуса не нужна — модальности нет. Кнопке — `aria-expanded`.

### 4.3 Чьё состояние

`dockOpen` — мебель страницы, как вкладки карточки: `useState` в
`TenderPage`, в URL не попадает (та же логика, что у `sidebarOpen` и у
фильтров реестра). Черновик чата переживает переключение вкладок карточки,
но умирает с уходом на другой тендер — осознанный долг уровня «фильтры не
сохраняются», записывается в `COMPONENTS.md` в тот же список.

## 5. Функционал панели: полный дубль прототипов

Заголовок: **«Анализ»**, подпись **«правила и ИИ · раунд 1»** (номер раунда —
из данных сравнения, не константа). Закрытие — крестик `IconButton ghost`
справа, sticky-шапка панели при скролле.

### 5.1 Соответствие прототипам — контрольный список

| В прототипах | Здесь | Отличие |
|---|---|---|
| 5 сценариев-чипсов: Что важно / Точки торгов / Сравнить подрядчиков / Риски и аномалии / Выбранное ★ | те же пять, тот же порядок | активный сценарий — рецепт 2 (текущее состояние), а не чёрная таблетка |
| сценарии bidding / anomalies переключают пресет таблицы | та же односторонняя связь | пресет живёт в `CompareToolbar`; сценарий дергает его наружу (§ 5.3) |
| карточки инсайтов: тег + заголовок + текст + мета «правило · сценарий» | те же четыре части | тексты выводятся из `analyzeComparison()`, а не захардкожены (§ 5.2) |
| теги факт / торг / риск | тоны neutral / warning / danger | тип `Tone` из `Badge`, никаких новых цветов |
| клик по карточке → подсветка строки + тост | подсветка + скролл к строке | **тост удалён**: скролл и вспышка сами — фидбек; лишний слой (`rule/smallest-intervention`) |
| «Спросить ИИ»: textarea + кнопка + блок «Ответ · демо» | тот же блок, те же демо-ответы | вызов спрятан за контракт `askAi()` (§ 5.4) |
| инфо-баннер «это статика» (v1) | не переносится | честность переезжает в метку «Ответ · демо» |
| чипсы истории запросов (v1) | не переносятся | декоративные; вернутся вместе с настоящей историей |
| ограничение «ровно два ★» для пары | читается из состояния избранного таблицы | тост прототипа заменяет карточка-приглашение (§ 6) |

### 5.2 Правила вместо цитат

Главное отличие от прототипов в данных. Прототипы хардкодили `INSIGHTS`;
в приложении уже существует вычислитель — `analyzeComparison()` в
`entities/tender` (медиана, разброс с меткой-порогом, минимум среди
НЕаномальных, вес, максимум потенциала) и предикаты `PREDICATES`. Сценарий —
это **срез тех же правил**, а не второй источник правды:

- «Что важно» — топ позиций по весу + позиции с `missing`/отказом у лидера;
- «Точки торгов» — позиции с потенциалом выше `POTENTIAL_MIN`, сортировка по нему;
- «Риски и аномалии» — ячейки с пометкой аномалии (`marks`), разброс
  `spreadTag: high`;
- «Сравнить подрядчиков» — разница итогов пары ★ с разложением по позициям;
- «Выбранное ★» — сводка по отмеченным колонкам.

Чистая функция `deriveInsights(comparison, favorites, scenario)` рядом с
моделью, самопроверка — расширение `comparison.check.ts` (конвенция проекта:
тихая ошибка здесь была бы тихой враньёй в карточках). Карточка несёт
`rowId` — тот же id, что у строк таблицы, поэтому клик-связка не знает
ничего о данных.

### 5.3 Связь с таблицей

Клик карточки → `focusRow(rowId)` → строка получает подсветку (фон
`--cu-state-hover`, тот же канал, что текущее состояние) и
`scrollIntoView({ block: 'center', behavior: 'smooth' })` внутри ленты.
Канал — проп `focusedRowId` вниз в `TenderCompare` + снятие фокуса по клику
в другую точку таблицы; никакого стора и событий.

Обратная связь «сценарий → пресет»: состояние пресетов поднимается из
`CompareToolbar` на уровень `TenderPage` (вниз — пропсы, вверх — колбэк),
сценарий вызывает его же сеттер, которым пользуется `Segmented`. Ручное
переключение пресета сценарий НЕ меняет — односторонняя связь прототипов
сохранена сознательно: сценарий — вопрос, пресет — настройка бинокля.

### 5.4 «Спросить ИИ»

Textarea (плейсхолдер «Спросите по отмеченным ★ или сценарию…») +
`Button variant="primary"` во всю ширину. Пустой ввод подставляет вопрос
по умолчанию — «Где выгоднее и где риски по отмеченным ★?» (поведение
прототипов сохранено дословно).

MVP отвечает демонстрацией: та же логика прототипов — при двух ★ заготовленная
выжимка пары («МетСнаб против ИнженерГрупп: дешевле на 316 тыс. ₽, основной
вклад — фундамент и бетон; проверить прогрев у МетСнаб и аномалии
СтройМонтажа»), иначе приглашение отметить двух подрядчиков с перечислением
текущего выбора. Блок ответа помечен **«Ответ · демо»** — метка честности,
унаследованная от v2/v3.

Контракт на будущее (M3): `async function* askAi(question, context)` в
слое фичи, `context` = срез сравнения + пара ★ + активный сценарий.
UI обязан уже сейчас знать три состояния потока — «думает» (ускоренная искра),
«стрим» (текст дописывается), «сбой» (обесцвеченная искра + повтор) — потому
что все три уже выражены скоростью глифа и не потребуют новой поверхности.

## 6. Матрица состояний (`rule/cover-reachable-states`)

| # | Состояние | Что видно | Действие |
|---|---|---|---|
| 1 | док закрыт | искра в строке названия | клик → открытие |
| 2 | док открыт, сценарий с данными | чипсы + карточки | клик карточки → строка |
| 3 | «Выбранное ★», звёзд < 2 | карточка-приглашение: «Отметьте двух подрядчиков ★ — появится разложение разницы» | правило `empty-state-action`: назван объект и первое действие |
| 4 | вопрос, ответ пуст ещё | кнопка в состоянии «думает», поле активно | повторный клик игнорируется |
| 5 | ответ получен (демо) | блок «Ответ · демо» | вопрос остаётся в поле (`rule/preserve-user-input`) |
| 6 | сбой (M3) | обесцвеченная искра, плашка ошибки с «Повторить» | `rule/error-states-recovery` |
| 7 | узкий контейнер | кнопка вернулась в поток, панель та же | § 3 |
| 8 | переход на другой тендер | панель закрыта, черновик очищен | осознанный долг, записан |

## 7. Что сознательно НЕ делаем

- **Тостов** по клику карточки — подсветка и скролл сами говорят «вот строка».
- **Сжатия контента сеткой** — оверлей, § 4.1.
- **Модальности и подложки** — анализ работает рядом с данными, не вместо.
- **URL-параметра openness** — мебель, не адрес.
- **Нового тона `--cu-tone-ai`** — семейство стопов глифа, не семантика.
- **Истории запросов и баннера «это статика»** из v1 — вернутся осмысленными
  или никогда.
- **Тёмной темы, RTL, виртуализации списка карточек** — потолок прототипов
  (≤7 карточек на сценарий) не требует.

## 9. Этапы

1. **M1 — призма без электричества.** Искра + панель + демо-ответы + связка
   со строками на `MOCK_COMPARISON`. Всё из этого ТЗ, кроме стрима.
2. **M2 — правила из модели.** `deriveInsights()` заменяет остатки хардкода,
   чек-скрипт, пресетная связка через поднятый состояние.
3. **M3 — живой ИИ.** `askAi()` к бэкенду, стрим в блок ответа, состояния
   4/6 матрицы становятся реальными. Интерфейс не меняется вообще — к этому
   ТЗ и писалось.
