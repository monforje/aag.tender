# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за проект

Начиналось как воспроизведение шелла ClickUp (топбар / иконный рейл / панель с
деревом) **с пиксельной точностью**; сейчас поверх этого шелла растёт продукт —
тендерная система. Отсюда два режима работы, и путать их нельзя:

- **каркас** (топбар, рейл, флайаут, сайдбар, дерево, обвязка страницы) —
  перенесён из эталона и менять его пиксели без просьбы нельзя;
- **продуктовые экраны** (реестр тендеров, карточка тендера) — эталона не
  имеют, решения по ним приняты по ходу и записаны в Часть XII `DESIGN-NOTES.md`.

Пакетный менеджер — **bun**. Стек: Vite 8, React 19, TypeScript 7, Zustand,
React Router 7, CSS Modules, `@solar-icons/react`.

## Команды

```bash
bun run dev        # дев-сервер на :5173
bun run build      # tsc --noEmit + vite build
bun run typecheck  # только проверка типов
```

Тестовой обвязки нет. Вместо неё — проверка целостности CSS-модулей:

```bash
python3 .claude/skills/fsd-component/scripts/check_css_modules.py
```

и два assert-скрипта там, где ошибка была бы тихой — не падает, а молча врёт:
разбор введённой даты (`31.02` без проверки превращается в 3 марта и меняет
выборку) и счётчик «осталось N дней» на карточке тендера (порог срочности и
склонение числа):

```bash
bun src/shared/lib/date.check.ts
```

```bash
bun src/entities/tender/model/registry.check.ts
```

Скрипт находит классы, объявленные в модуле, но не применённые ни одним его
потребителем: это либо мёртвое правило, либо селектор, ушедший в чужой модуль
(см. «Стили»). Норма — ноль.

## Эталон

`reference/index.html` — исходный монофайл (2386 строк), из которого перенесён
весь каркас. **В рабочей копии его сейчас НЕТ**: папка `reference/` удалена, и
инструкции «открыть рядом с приложением и сверить пиксели» сегодня выполнить
нечем. Единственный его след — **`DESIGN-NOTES.md`**: все 156 комментариев
эталона дословно, разложенные по слоям, с разбором. Ссылки вида `§4.8-a` в коде
указывают на разделы эталона и расшифрованы там же.

Практическое следствие: **проверять правки в каркасе теперь можно только по
`DESIGN-NOTES.md` и по самому коду**, а не численной сверкой. Тем более важно
не менять числа каркаса «заодно». Если эталон вернут в рабочую копию, порядок
сверки описан в Части XI и в скилле `fsd-component`.

**`COMPONENTS.md`** — реестр компонентов: что есть, где лежит, когда брать.
**Обновлять при добавлении компонента**, иначе его не найдут и продублируют.

## Архитектура

FSD, зависимости только вниз: `app → pages → widgets → features → entities → shared`.

```
app/       точка входа, роутер, global.css (токены + reset + каталог состояний)
pages/     экраны под маршрутами: tender-registry (реестр) и tender (карточка
           за строкой реестра). Других страниц в приложении сейчас нет
widgets/   topbar, rail, sidebar, workspace — каркас, по одному экземпляру
features/  flyout — превью-панель раздела при наведении на рейл
entities/  section (данные рейла и деревьев), tender (реестр, статусы,
           фильтры, tenderPath), workspace (стор)
shared/    примитивы: IconButton, Button, Badge, Table, SearchInput,
           FacetFilter, Calendar, DatePicker, RangeCalendar, InlineInput,
           Dropdown, Popover, Modal, TreeRow, ScrollArea…
           lib: cx, date, toggle
```

Две страницы одного домена данные не делят через импорт друг друга — общее
уезжает в `entities/`. Так реестр (`pages/tender-registry`) и карточка
(`pages/tender`) читают `entities/tender`.

Импорты — только через публичную точку слайса (`@/shared/ui/IconButton`).
Глубоких импортов в проекте нет ни одного.

### Состояние

- **URL — источник истины** для `activeId` (раздел рейла): в стор он
  проецируется из маршрута, и делает это **одно место** — `RouteSync` в
  `app/providers/router.tsx`. Навигация всегда через `navigate()`; произвольная
  запись в стор создаст второго писателя, и адрес разъедется с подсветкой.
  Ровно одно исключение — `selectSection()`: клик по рейлу раскрывает сайдбар и
  показывает дерево раздела, не меняя страницу, потому что у разделов
  «Контрагенты», «Справочники» и «Администрирование» своих экранов нет.
- **Собственное состояние стора** — `sidebarOpen`. Это положение мебели, в URL
  ему не место.
- Подсветка пункта дерева живёт на любом вложенном маршруте
  (`activePath.startsWith(path + '/')`), иначе на карточке тендера дерево
  показывало бы, что мы «нигде».
- **Фильтры реестра в URL не попадают** — осознанный долг: ссылку на
  отфильтрованный реестр не отправить, F5 сбрасывает.

### Стили

- **Классы в `.module.css` названы как в эталоне** (`.row__title`, `.is-active`)
  — чтобы DevTools и `DESIGN-NOTES.md` совпадали. В TSX доступны в camelCase
  (`s.rowTitle`) благодаря `localsConvention: 'camelCaseOnly'`.
- **Селектор не пересекает границу CSS-модуля.** Классы хэшируются помодульно,
  поэтому `.parent .child` из разных модулей не совпадает ни с чем — молча, без
  ошибок сборки. Так дважды ломались тень липкой шапки и проявление контролов
  сайдбара. Выходы: состояние пропом-модификатором на самом элементе;
  CSS-переменная как мост (наследуется по DOM, хэшей не имеет); класс, отданный
  наружу самим модулем (`tableCell` у `Table`, `searchSecondaryIconClass` у
  `SearchTrigger`); либо держать сцепленные `:has()`-правилами стили в одном
  модуле, даже если компоненты разные.
- **Класс-модификатор, сцепленный с тегом, бьёт по специфичности.** `.table td`
  — это (0,1,1), а одиночный класс (0,1,0), поэтому правила вида
  «эта колонка вправо» и «у пустой строки просторный паддинг» обязаны
  писаться `.table td.cell--numeric`. Дважды поймано именно здесь.
- **Состояния берутся из шкалы**, новые альфы не заводятся. Токены
  `--cu-state-hover-subtle` (.05, крупная поверхность), `--cu-state-hover` (.06,
  компактный контрол и текущее состояние), `--cu-state-hover-strong` (.09,
  поверх собственной заливки) плюс каталог из десяти рецептов взаимодействия —
  всё в `app/styles/global.css`.
- **Семантические тона — тоже токены** (`--cu-tone-*`): цвет, `-ink` для текста
  поверх заливки и `-fill` для самой заливки. Тип `Tone` живёт в
  `shared/ui/Badge`; доменные таблицы статусов типизируются им.
- **Reset уже даёт кнопке** `background:none; border:0; font:inherit;
  cursor:pointer`. Повторять это в каждом модуле не нужно.
- **Варианты, а не оси.** `IconButton`, `Avatar`, `Button` принимают `variant`
  (поверхность или роль), а не `size`+`radius`: у оригинала радиусы не следуют
  размеру (28px→7px, 32px→6px, 32px на рейле→8px), и свободные числа
  разъезжаются с эталоном при первом же новом вызове.
- **`<col>` игнорирует процент внутри `calc()`/`clamp()`.** Вся декларация
  молча откатывается в `auto`: `clamp(176px, 20%, 280px)` не работает,
  `clamp(176px, 20cqw, 280px)` работает. Поэтому арифметика ширины колонок
  идёт в `cqw`, а `.table-wrap` объявлен `container-type: inline-size`. Плюс
  второе: при авторазметке `width` у `<col>` — вообще лишь пожелание, ширины
  исполняются только при `<Table layout="fixed">`. Разбор и замеры — Часть XII
  `DESIGN-NOTES.md`.

### Продуктовые экраны (вне эталона)

Разбор решений — **Часть XII `DESIGN-NOTES.md`**; коротко то, что придётся
соблюдать в следующем экране:

- **Колонка контента — 12px** от левого края `<main>`. На этой линии стоят
  заголовок страницы, первая вкладка и первая колонка таблицы. Ради неё
  таблица идёт от края до края (`margin-inline: -12px`), а 12px держит паддинг
  ячейки: рамка блока иначе всегда толкает текст правее.
- **Статус описан один раз** — `STATUS` в `entities/tender` (подпись, тон,
  иконка). Таблица и фильтры только читают: одно состояние — один цвет и один
  глиф везде.
- **Геометрия таблицы снята с shadcn/ui `<Table>`**, палитра — наша. Отступления
  (заливка шапки, отсутствие зебры, `<caption>` со счётчиком) объяснены там же.
- **Контролы разного веса**: ряд одинаковых кнопок читается как забор. Поиск —
  капсула во всю ширину, период и фильтры — `IconButton variant="topbar"`
  (тот же компонент, что календарь в топбаре, а не его копия), статус —
  `Button variant="secondary"`.
- **Фильтр по полю с многими значениями** — `FacetFilter`: две колонки
  (критерии | значения) с поиском внутри критерия, потолком в 50 строк и
  закреплённым выбранным. Стопка групп не масштабируется.
- **Мультивыбор внутри `Dropdown` — это `closeOnSelect={false}`**, а не
  `stopPropagation` в содержимом: штатно меню закрывается по клику в нём, а
  значения выбирают сериями.
- **Колонки, которые СРАВНИВАЮТ, ширину по содержимому брать не должны.**
  Авторазметка меряет колонку по самому длинному значению — у подрядчика с
  длинным именем колонка шире, хотя читают их как равные. Лечится
  `<Table layout="fixed">` плюс вилкой на `<col>`: пол, потолок и равная доля
  остатка, посчитанная ОДИН раз на всех. Цена режима — обрезка, поэтому
  колонке-якорю нужен `title` с полным текстом.
- **Значение, которое правят на месте, в покое выглядит как ТЕКСТ.** Ни рамки,
  ни заливки, тот же кегль, что у нередактируемого соседа: экран из четырёх
  обведённых полей читается как анкета, а сводку в первую очередь читают.
  Поверхность общая и глобальная — `.inline-edit` в `global.css` (раздел 1-b),
  её делят `<InlineInput>` и кнопка `<DatePicker>`. Нехэшированная намеренно:
  элементы РАЗНЫХ типов из РАЗНЫХ модулей, селектор модуля туда не дотянется, а
  компонентом общая у них не разметка, а поверхность.
- **Календарь в проекте ОДИН.** `<CalendarMonth>` (`shared/ui/Calendar`) —
  сетка месяца с геометрией shadcn/ui; поверх неё `<DatePicker>` (одна дата) и
  `<RangeCalendar>` (период). Третьей сетки быть не должно: граница проведена
  по вопросу «кто знает смысл выбранного дня» — сетка не знает, потребитель
  отдаёт это через `DayState`. При этом ФОН КНОПКИ дня задаётся флагами
  (`selected`, `plain`), а не классом снаружи: `today`, «выбран» и «без фона» —
  все три одиночные классы, и разъедься они по модулям, спор решал бы порядок
  файлов в сборке.
- **Нативный `<select>` в панели — нельзя.** Раскрытый список рисует ОС, и
  внутри своей панели открывается меню чужой эпохи; `<option>` не стилизуется.
  Приём shadcn `captionLayout="dropdown"` по этой причине из шапки календаря
  убран.
- **Окно и выпадашка — нативный `<dialog>`**: `<Modal>` и `<Popover>` в
  `shared/ui`. Фокус, Escape, подложка и верхний слой достаются от платформы,
  и переписывать это руками нельзя. Выпадашка тоже `<dialog>` не из
  эстетики: она обязана выйти за пределы прокручиваемого родителя, а обрезка
  к `z-index` отношения не имеет. Открытость — ПРОП (`open` / `anchor`), а не
  `ref.showModal()` у потребителя: иначе «окно открыто» знают двое, и Escape
  разводит их первым же нажатием.

## Иконки

`shared/ui/Icon/icon-map.ts` — таблица «id спрайта эталона → компонент»,
составленная сопоставлением геометрии путей, а не имён (у Solar другие
названия: `search→Magnifier`, `myTasks→Checklist`, `grid→Widget5`). Четыре
иконки рейла (`docs`, `funnel`, `target`, `planet`) в Solar отсутствуют и живут
в `local-icons.tsx` с путями из эталона.

Иконки, которых в СПРАЙТЕ эталона не было, добавляются свободно (`closeCircle`):
экраны вне эталона рисуются Solar напрямую. Раньше крестик изображали иконкой
`add`, повёрнутой на 45°, — этот приём убран.

Размер и толщина задаются CSS (`.icon svg`), а не пропами Solar — так было в
спрайте, и так сохраняется 1:1.

## Создание нового UI

Есть скилл `fsd-component` (`.claude/skills/fsd-component/`): выбор слоя,
скаффолд файлов, JSDoc-шаблон, обновление `COMPONENTS.md`. Он же напоминает
главное правило — **сначала проверить, нет ли готового**: исторически в этом
коде было по 6 копий кнопки-иконки, по 3 копии аватара и по 4 копии белой
кнопки 32px в одном модуле фильтров.

JSDoc над каждым компонентом обязан отвечать на четыре вопроса: **КОГДА**,
**НЕ ДЛЯ** (со ссылкой на альтернативу), **UX**, **A11Y**. Раздел «НЕ ДЛЯ» —
не формальность: без него через месяц появляется дубликат.
